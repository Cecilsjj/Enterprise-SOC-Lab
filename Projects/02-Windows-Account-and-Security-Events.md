# Project 02 – Windows Account and Security Events

## Objective

Investigate Windows Security events related to account activity, logoff activity, privileged logons, user account creation, and user account deletion using Windows Event Viewer.

## Key Concepts

SOC stands for **Security Operations Center**.

Windows Event Viewer is used to review system, application, and security logs on Windows systems.

Windows Security logs help analysts investigate authentication activity, account activity, privilege use, and suspicious behavior.

In this project, I investigated the following Windows Event IDs:

| Event ID | Meaning |
|---:|---|
| 4634 | An account was logged off |
| 4672 | Special privileges assigned to a new logon |
| 4720 | A user account was created |
| 4726 | A user account was deleted |
| 4740 | A user account was locked out |

## Tools Used

- Windows Event Viewer
- Windows Security Logs
- Event ID filters
- PowerShell
- Screenshots
- Copied event details as text

## Event ID 4634 – Account Logged Off

I filtered the Windows Security log for:

```text
4634
```

The event showed:

```text
An account was logged off.
```

Observed details included:

```text
Account Name: cecil
Logon ID: 0x21619FE0
Logon Type: 7
```

## Logon Type 7 Explanation

Logon Type 7 means:

```text
Unlock
```

This means the event was related to workstation unlock activity. The Logon ID can be used to correlate the logoff event with related logon activity.

## Event ID 4672 – Special Privileges Assigned

I filtered the Windows Security log for:

```text
4672
```

Event ID 4672 means:

```text
Special privileges assigned to a new logon.
```

Observed details included:

```text
Account Name: SYSTEM
Privileges: SeAssignPrimaryTokenPrivilege, SeTcbPrivilege, and others
```

## Privilege Event Explanation

The SYSTEM account is a built-in Windows account used by the operating system and services.

Seeing special privileges assigned to SYSTEM can be normal Windows behavior. However, Event ID 4672 is important because privileged logons should always be reviewed during investigations.

If these privileges appeared under an unknown or suspicious user account, it would require deeper investigation.

## Event ID 4720 – User Account Created

At first, no existing Event ID 4720 events were found.

To safely generate this event, I created a temporary local test user using Administrator PowerShell.

Command used:

```powershell
net user soclabtest TestPassword123! /add
```

Expected result:

```text
The command completed successfully.
```

After creating the account, I filtered the Security log for:

```text
4720
```

The event showed that a user account was created.

Observed account:

```text
soclabtest
```

## Event ID 4726 – User Account Deleted

After generating the account creation event, I deleted the temporary test user.

Command used:

```powershell
net user soclabtest /delete
```

Expected result:

```text
The command completed successfully.
```

After deleting the account, I filtered the Security log for:

```text
4726
```

The event showed that a user account was deleted.

Observed account:

```text
soclabtest
```

## Event ID 4740 – Account Locked Out

I filtered the Windows Security log for:

```text
4740
```

No account lockout events were found.

This is normal on a personal Windows machine if no account lockouts occurred.

## Findings

- Event ID 4634 confirmed account logoff activity.
- The observed 4634 event involved account `cecil`.
- Logon Type 7 was identified as workstation unlock-related activity.
- Event ID 4672 confirmed special privileges assigned to a new logon.
- The observed 4672 event involved the SYSTEM account.
- SYSTEM receiving special privileges can be normal operating system behavior.
- Event ID 4720 was generated by creating a temporary local test user.
- Event ID 4726 was generated by deleting the temporary local test user.
- Event ID 4740 was not found because no account lockout activity was observed.
- Screenshots and copied event details were saved as evidence.

## Security Lessons Learned

- Windows Security logs can show account logoff, privilege, creation, deletion, and lockout activity.
- Event ID 4634 helps identify when an account logs off.
- Event ID 4672 helps identify privileged logons.
- Event ID 4720 is important because unexpected account creation can indicate unauthorized access or persistence.
- Event ID 4726 is important because unexpected account deletion can indicate account tampering or cleanup activity.
- Event ID 4740 is useful for detecting account lockouts, which may indicate password guessing or brute-force attempts.
- SYSTEM activity can be normal, but privileged events should still be reviewed.
- Controlled test events help analysts understand what normal and suspicious activity looks like.
- Evidence should be saved using screenshots and copied event details.
